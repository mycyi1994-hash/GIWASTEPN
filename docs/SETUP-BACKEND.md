**약 40분 · 전부 무료 · 순서대로 하시면 됩니다**

## 왜 필요한가

지금 앱은 모든 걸 폰 안에만 저장합니다. **기기를 바꾸면 그동안 모은 SUP와
스니커즈가 전부 사라집니다.** 온체인으로 가지 않기로 했으니, 서버가 유일한
보관처입니다. 그래서 계정과 서버가 v1에서 가장 중요합니다.

## 🔐 먼저 — 보내도 되는 것과 안 되는 것

| 값 | 저에게 | 이유 |
|---|:--:|---|
| Supabase **Project URL** | ✅ | 앱에 그대로 박히는 공개 주소 |
| Supabase **anon public** 키 | ✅ | **공개용으로 설계된 키**입니다. 앱에 넣으라고 주는 값이고, 이것만으로는 권한 규칙(RLS)을 못 넘습니다 |
| Google **웹 클라이언트 ID** | ✅ | 공개 값 |
| SHA-1 지문 | ✅ | 공개 값 |
| Supabase **service_role** 키 | ❌ | **절대 금지.** 모든 권한을 무시하는 마스터 키입니다 |
| Google **클라이언트 보안 비밀** | ❌ | Supabase 화면에만 붙여넣으세요 |
| 지갑 개인키 · 시드 문구 | ❌ | 이 작업에는 아예 필요 없습니다 |

> 헷갈리시면 **아무것도 안 보내고 화면 캡처만** 주셔도 됩니다. 제가 어느 값인지
> 짚어 드리겠습니다. 단, 캡처에 `service_role`이 보이면 가려 주세요.

# 1단계 · Supabase 프로젝트 만들기

데이터베이스 + 로그인 + 실시간 동기화를 한 번에 주는 서비스입니다. 무료 등급으로
충분합니다.

1. `supabase.com` 접속 → **Start your project**
2. **Sign in with GitHub** (이미 GitHub 쓰시니 가장 빠릅니다)
3. **New project** 클릭
4. 입력합니다.

| 항목 | 값 |
|---|---|
| **Name** | `stepup` |
| **Database Password** | 자동 생성 버튼을 누르고 **비밀번호 관리자에 저장**하세요. 다시 볼 수 없습니다 |
| **Region** | **Northeast Asia (Seoul)** — 사용자가 한국이면 응답이 가장 빠릅니다 |
| **Plan** | Free |

5. **Create new project** → 프로비저닝에 1~2분 걸립니다.

### 값 찾기

프로젝트가 만들어지면 왼쪽 아래 **⚙ Project Settings → API** 로 갑니다.

| 화면에 보이는 것 | 저에게 보낼 것 |
|---|:--:|
| **Project URL** (`https://xxxxx.supabase.co`) | ✅ |
| **Project API keys → `anon` `public`** | ✅ |
| **Project API keys → `service_role` `secret`** | ❌ 보내지 마세요 |

✅ **확인:** Project URL과 anon 키 두 개를 복사해 두셨으면 1단계 끝입니다.

# 2단계 · Google 로그인 등록

구글 계정으로 로그인하려면 구글에 "이 앱이 로그인을 씁니다"라고 등록해야 합니다.

## 2-1. 프로젝트 만들기

1. `console.cloud.google.com` 접속
2. 상단 프로젝트 선택 → **새 프로젝트** → 이름 `StepUp` → **만들기**
3. 만들어진 프로젝트가 선택됐는지 확인

## 2-2. 동의 화면 설정

1. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**
2. **External(외부)** 선택 → **만들기**
3. 입력합니다.

| 항목 | 값 |
|---|---|
| 앱 이름 | `StepUp` |
| 사용자 지원 이메일 | 본인 이메일 |
| 개발자 연락처 이메일 | 본인 이메일 |

4. **저장 후 계속** → 범위(Scopes)는 건드리지 말고 계속 → 테스트 사용자도 그냥 계속

> 심사(게시)는 나중에 해도 됩니다. 테스트 단계에서는 본인 계정으로 로그인됩니다.

## 2-3. 클라이언트 ID 2개 만들기

**API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**

### ① 웹 애플리케이션 (필수)

| 항목 | 값 |
|---|---|
| 애플리케이션 유형 | **웹 애플리케이션** |
| 이름 | `StepUp Web` |
| **승인된 리디렉션 URI** | `https://<1단계의-프로젝트-주소>/auth/v1/callback` |

> 예: Project URL이 `https://abcdefgh.supabase.co` 라면
> `https://abcdefgh.supabase.co/auth/v1/callback`

만들면 **클라이언트 ID**와 **클라이언트 보안 비밀** 두 개가 나옵니다.
**둘 다 따로 적어 두세요** — 3단계에서 씁니다.

### ② Android (필수)

| 항목 | 값 |
|---|---|
| 애플리케이션 유형 | **Android** |
| 이름 | `StepUp Android (debug)` |
| **패키지 이름** | `com.giwa.strideup` |
| **SHA-1 인증서 지문** | 아래 값 그대로 |

```
34:ED:A6:73:DF:C6:27:FD:AF:D1:06:C0:A0:05:91:1C:AF:59:8A:EC
```

> 이건 저장소에 있는 **디버그 키**의 지문입니다. 개발·테스트용이고 공개해도
> 안전합니다. Play Store에 올릴 때는 구글이 주는 다른 지문을 하나 더 등록해야
> 하는데, 그건 Play Console 등록이 끝난 뒤에 알려 드리겠습니다.

# 3단계 · Supabase에 구글 연결

1. Supabase 대시보드 → 왼쪽 **Authentication → Providers**
2. 목록에서 **Google** 을 찾아 켭니다
3. 2-3 ①에서 받은 값을 붙여넣습니다.

| 칸 | 넣을 값 |
|---|---|
| **Client ID** | 웹 클라이언트 ID |
| **Client Secret** | 웹 클라이언트 보안 비밀 |

4. **Save**

✅ **확인:** Google 항목이 **Enabled** 로 바뀌면 끝입니다.

---

# 4단계 · 저에게 전달

아래 세 개만 주시면 됩니다.

```
Supabase Project URL : https://xxxxx.supabase.co
Supabase anon key    : eyJhbGci...
Google 웹 클라이언트 ID : xxxxx.apps.googleusercontent.com
```

전부 앱에 그대로 들어가는 **공개 값**입니다. 받으면 앱에 연결하고,
데이터베이스 스키마를 올린 뒤 실제 로그인이 되는지 같이 확인하겠습니다.

# ❓ 막혔을 때

| 증상 | 해결 |
|---|---|
| Supabase 프로젝트 생성이 계속 돌아감 | 1~2분 걸립니다. 5분 넘으면 새로고침 |
| 리디렉션 URI 형식 오류 | `https://` 로 시작하고 끝에 `/auth/v1/callback` 이 붙었는지 확인. 슬래시 하나 차이로 거절됩니다 |
| OAuth 동의 화면에서 막힘 | 범위·테스트 사용자는 전부 건너뛰어도 됩니다. "저장 후 계속"만 누르세요 |
| 어떤 키를 보내야 할지 모르겠음 | 화면 캡처를 주세요 (단, `service_role` 부분은 가려서) |
| 값이 틀렸는지 확인하고 싶음 | 일단 보내 주세요. 형식이 틀리면 제가 바로 알 수 있습니다 |

**막히시면 어느 단계에서 뭐가 안 되는지만 알려 주세요.**
